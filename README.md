# Free University · 열린 교실

교실은 전공을 담는 그릇이고, 어느 전공의 집도 아니다.

- 무료. 학위·학점·자격·수료증 없음.
- 기준 전공 없음. 첫 화면은 학과 선택이고, 계열과 학과 모두 가나다순.
- 진도와 제출한 글은 이 브라우저에만 저장. 서버·계정·추적 없음.

## 실행

의존성은 없다. Node 18 이상.

```bash
npm run serve        # http://localhost:8123
npm test             # 채점 엔진·스키마 단위 테스트
npm run check        # 콘텐츠·원칙 검사 (CI용)
```

`index.html`을 파일로 직접 열면 콘텐츠를 읽지 못한다. 반드시 서버로 연다.

## 범위 결정

**면허·자격이 목적인 학과는 넣지 않는다.** 의학, 간호, 약학, 식품영양(영양사)을 뺐고, 그래서 보건 계열이 없어졌다. 보건행정학은 면허와 무관하므로 사회 계열로 옮겼다.

교육 계열은 이론만 다룬다. 교원 자격과는 무관하고, 실습은 제출형으로만 남긴다. 법학, 심리학, 재무학, 사회복지학처럼 조언이나 실무로 오해받을 수 있는 학과는 카탈로그 소개에 범위 밖인 것을 적어 두었다.

현재 상태: 7개 계열, **51칸이 모두 열려 있다**(면허가 필요한 학과는 처음부터 제외). 51개 학과 모두 공통 줄기 6교시씩 갖추어 전체 **306교시**다.

| 계열 | 학과 |
|---|---|
| 경영 | 경영학, 국제통상학, 마케팅, 재무학, 회계학 |
| 공학 | 건축학, 기계공학, 산업공학, 신소재공학, 전자전기공학, 컴퓨터공학, 토목공학, 화학공학, 환경공학 |
| 교육 | 교과교육, 교육학, 유아교육, 특수교육 |
| 사회 | 경제학, 문헌정보학, 미디어커뮤니케이션, 법학, 보건행정학, 사회복지학, 사회학, 심리학, 인류학, 정치외교학, 지리학, 행정학 |
| 예술 | 디자인, 미술, 연극영화, 음악, 체육학 |
| 인문 | 국어국문학, 독어독문학, 사학, 언어학, 영어영문학, 일어일문학, 중어중문학, 철학, 프랑스어문학 |
| 자연 | 물리학, 생명과학, 수학, 지구과학, 천문학, 통계학, 화학 |

디자인을 포함한 모든 학과에서 형식·개념 분석은 채점하고, 직접 해 보는 과제는 글로 남기고 스스로 점검하는 흐름이 예외 처리 없이 같은 화면에서 돌아간다. 모든 그림은 이 저장소 안의 직접 만든 SVG다.

**AI는 만드는 단계에서만 쓴다.** 원고와 그림(SVG)은 저장소에 파일로 올려 두고, 사이트는 그 파일을 그대로 서빙한다. 실행 중에는 AI도 유료 API도 호출하지 않으므로 사용자가 늘어도 비용이 늘지 않는다. `npm run check`가 이 원칙을 지킨다(외부 주소, API 키, 외부 호출 코드가 하나라도 있으면 실패. 허용 목록은 비어 있다).

**외부 연동이 없다.** 수식 렌더러(KaTeX 0.16.9, MIT)도 `vendor/katex/`에 복사해 두었다. 수식을 선언한 교시에서만 불러오고, 다른 학과는 이 파일을 받지 않는다. 외국어 발음 듣기(`speech:*`)와 음높이·화음 합성(`tone`) 역시 브라우저 내장 기능(Web Speech·Web Audio)만 쓰며 외부 요청이 없다.

**검수와 신고.** 교시마다 "검수 전 · AI 초안 / 검수됨 / 검수 뒤 내용이 바뀜"이 표시되고, "틀린 곳 알리기"로 신고문을 만들 수 있다. 신고문은 자동 전송되지 않고, 받는 곳은 `content/site.json`에서 정한다(지금은 비어 있음). 절차는 `docs/REVIEW.md`, 현황은 `npm run review`.

**원고는 초안이다.** 학과 원고는 모두 AI가 쓴 초안이고 사람의 검수를 거치지 않았다. 계산형 문항은 정답을 독립적으로 다시 계산해 확인했고 그림 293개는 기계 검사와 눈 확인을 거쳤지만, 사실·문법·용어(특히 외국어문학 4개)는 사람이 확인해야 한다. 공개 전에 작성자가 아닌 사람이 사실과 난이도를 확인해야 한다. 집필 규칙은 `docs/AUTHORING.md`에 있다.

## 구조

```
content/
  fields.json                 계열 (찾기용, 서열 아님)
  catalog.json                학과 칸 전체 (이름, 계열, 상태, 소개)
  departments/<id>.json       열린 학과의 줄기·갈래·교시
src/
  engine/                     DOM 없는 순수 로직 (Node에서도 돌아감)
    checks.js                 채점 엔진 하나 + 문항 유형 등록부
    expr.js                   수식 해석·동치 판정 (eval 없음)
    schema.js                 학과 데이터 검증
    progress.js               선행·잠금·진도 규칙
    search.js                 학과 요약 및 교시 본문 통합 검색
    connections.js            학과 간 공유 개념 및 연계 학과 탐색
    review.js                 검수 상태 계산 및 검증
    report.js                 오류 신고문 생성
  views/                      모든 학과가 같은 화면을 쓴다
  features.js                 교시가 선언할 때만 불러오는 기능 (formula, speech:*, tone)
vendor/katex/                 수식 렌더러 (저장소 안에 복사)
tools/review.mjs              검수 현황·기록 (docs/REVIEW.md)
tools/check.mjs               CI 검사
```

## 학과 추가하기 (화면 코드는 고치지 않는다)

1. `content/departments/<id>.json`을 만든다. `mathematics.json`이나 `philosophy.json`을 본으로 삼는다.
2. `content/catalog.json`에서 그 학과의 `status`를 `"open"`으로 바꾸고 `audience`와 `file`을 넣는다.
3. `npm run check`를 돌린다.

`src/`를 고쳐야 한다면 틀이 잘못된 것이다. 학과를 고치지 말고 틀을 고친다.

### 교시 형식

```jsonc
{
  "id": "phil-01",
  "title": "논증의 구조",
  "minutes": 20,
  "requires": [],              // 같은 학과의 교시만. 비어 있으면 입구
  "features": [],              // "formula", "speech:de", "tone" 등 필요한 기능만 선언
  "version": 1,                // 내용을 크게 고치면 올린다 → 이미 마친 사람에게 "내용 갱신됨"
  "explain": ["문단 또는 목록 블록", { "figure": "departments/<학과>/그림.svg", "alt": "대체 텍스트(필수)", "caption": "선택" }],
  "examples": [{ "title": "...", "body": ["..."] }],
  "checks": [ /* 문항 */ ]
}
```

### 문항 유형

| type | 판정 | 필수 필드 |
|---|---|---|
| `numeric` | 값 비교, `tolerance` 선택. `1/2`, `2pi`, `1,200` 같은 입력도 받는다 | `answer` |
| `expression` | 여러 점에서 값을 넣어 같은 식인지 판정. `upToConstant`이면 적분 상수 허용. `features: ["formula"]` 필요 | `answer`, `vars` |
| `choice` | 정답 번호와 일치. 정답이 둘 이상이면 복수 선택 | `options`, `answer` |
| `match` | 모든 짝 일치 | `pairs` |
| `order` | 순서 일치 (`items`는 정답 순서로 적는다) | `items` |
| `keywords` | 동의어 묶음이 모두 있으면 **통과가 아니라** 모범 답안 비교 → 자기 확인 | `groups`, `model`, `selfCheck` |
| `submit` | 채점하지 않는다. 글을 남기고 자기 점검표를 모두 확인하면 통과 | `checklist` |

문항에는 `figure: { figure, alt }`를 붙여 그림을 보여 줄 수 있다. 그림 경로는 `content/` 기준이고, `alt`가 없으면 검사가 실패한다.

모든 문항에 `prompt`가 필요하다. `hint`(2번 틀리면 보임)와 `explanation`(3번 틀리거나 맞히면 보임)은 선택이지만 넣는 것을 권한다.

자기 확인으로 통과한 교시는 진도에 "자기 확인 포함"으로 따로 표시한다. 숨기지도 낮추지도 않는다.

## `npm run check`가 지키는 원칙

1. 카탈로그와 학과 데이터가 스키마에 맞는다. 입구가 있고, 순환이 없고, 다른 학과의 교시를 선행으로 요구하지 않는다.
2. 교시가 선언한 기능을 화면이 알고 있다.
3. **`src/`와 `index.html`에 학과 id나 이름이 하나도 없다.**
4. **어느 학과를 하나 빼도, 학과가 0개여도 교실이 성립한다.** (52가지 구성)
5. 열린 학과마다 입구에서 모든 교시를 끝까지 풀 수 있고, 정답은 통과하고 오답은 통과하지 않는다.
