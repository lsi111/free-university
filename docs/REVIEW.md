# 검수와 오류 신고

학과 원고는 AI가 쓴 초안이다. 사람이 읽고 확인하기 전까지 교시마다 "검수 전 · AI 초안"으로 표시된다. 이 표시는 지우지 않고, 검수 기록이 생기면 저절로 바뀐다.

## 검수자

- **작성자와 다른 사람**이 한다. 원고를 쓴 에이전트나 그 원고를 만든 사람이 자기 원고를 검수하지 않는다.
- 이름은 실명이거나 별칭이어도 된다. 화면에 그대로 보인다.
- 검수는 **교시 단위**다. 한 교시를 끝까지 읽고 문항을 직접 풀어 본 뒤 기록한다.

## 교시 하나의 체크리스트

1. **사실**: 설명과 예의 모든 주장이 맞는가. 숫자, 연대, 정의, 이름. 불확실하면 고치거나 뺀다.
2. **균형**: 논쟁이 있는 주제를 한쪽 답으로 쓰지 않았는가. 특정 정당·인물·집단을 평가하지 않았는가.
3. **문항**: 정답이 하나로 정해지는가. 해석에 따라 갈리는 문항은 없는가. 오답 선택지가 사실상 정답이 아닌가. `hint`와 `explanation`이 맞는가.
4. **그림**: 눈으로 열어 보았는가. 글자가 넘치거나 겹치지 않는가. `alt`가 그림에 **보이는 것만** 말하는가(정답을 알려 주지 않는가).
5. **난이도**: 비전공자가 20~35분에 끝낼 수 있는가. 처음 나오는 용어가 정의되어 있는가.
6. **범위**: 진단, 처방, 법률·투자 조언, 자격·실무 판단처럼 읽히는 문장이 없는가.
7. **직접 풀기**: 사이트에서 교시를 실제로 끝까지 풀어 본다. 정답이 통과하고, 일부러 틀린 답이 막히는지 본다.

고칠 것이 있으면 원고를 고친다. **내용을 크게 바꿨으면 그 교시의 `version`을 올린다.** 오탈자만 고쳤다면 올리지 않아도 된다.

## 기록 남기기

```bash
node tools/review.mjs add <학과id> <교시id> --reviewer "이름" --notes "고친 것 한 줄"
node tools/review.mjs add <학과id> all --reviewer "이름"     # 학과 전체를 한 번에
npm run review                                                # 현황 보기
```

기록은 `content/reviews.json`에 쌓인다. 검수한 당시의 교시 `version`이 함께 저장된다. 그 뒤에 교시의 `version`이 올라가면 화면에는 "검수 뒤 내용이 바뀜"으로 표시되고, 다시 검수해야 "검수됨"이 된다.

`npm run check`는 기록이 없는 교시나 날짜 형식, 더 높은 버전을 가리키는 기록을 오류로 잡는다.

## 오류 신고

모든 교시 끝에 "틀린 곳 알리기"가 있고, 문항마다 "이 문항 신고" 링크가 있다. 학습자가 위치, 종류, 내용을 적으면 **신고문이 이 화면에서만 만들어진다.** 어디로도 자동 전송되지 않는다. 서버가 없기 때문이고, 학습자의 정보가 새지 않게 하려는 의도다.

신고를 받을 곳은 `content/site.json`에서 정한다.

```json
{
  "reportEmail": "받을 메일 주소 또는 null",
  "reportUrl": "https://… (이슈 작성 페이지 등) 또는 null"
}
```

- `reportEmail`이 있으면 신고문과 함께 "메일로 보내기" 링크가 보인다. 학습자가 누르면 학습자의 메일 앱이 열린다.
- `reportUrl`이 있으면 "신고 페이지 열기" 링크가 보인다. 학습자가 신고문을 붙여 넣는다.
- 둘 다 `null`이면 신고문을 복사하라고 안내한다. 이 경우 신고는 실제로 어디에도 도착하지 않는다는 점을 문구로 정직하게 알린다.

받는 곳이 정해지기 전에 공개하지 않는 것이 좋다.

## 신고를 받은 뒤

신고문에는 학과 id, 교시 id, 내용 버전, 위치가 들어 있어 어느 문항인지 바로 찾을 수 있다. 확인한 뒤 원고를 고치고, 크게 바꿨다면 `version`을 올린 다음 다시 검수 기록을 남긴다.
