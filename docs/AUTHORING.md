# 학과 원고 집필 가이드

Free University의 학과 하나를 채우는 사람(또는 에이전트)을 위한 규칙이다. 형식의 전체 설명은 `README.md`에 있다. 본으로 삼을 파일은 `content/departments/philosophy.json`(글 중심)과 `content/departments/design-studies.json`(그림 중심)이다.

## 만들 것

- `content/departments/<학과id>.json` 하나.
- 그림이 필요하면 `content/departments/<학과id>/` 아래 SVG 파일들.
- 이 밖의 파일은 건드리지 않는다. 특히 `src/`, `tools/`, `content/catalog.json`, `README.md`는 수정 금지다. 카탈로그는 원고가 통과한 뒤 편집자가 연다.

## 원칙

1. **웹사이트 안에서 끝나야 한다.** 외부 이미지, 외부 링크가 필요한 문항, 외부 API, 웹폰트, 오디오를 쓰지 않는다. 그림은 직접 만든 SVG다. 수식은 `features`에 `"formula"`를 선언한 교시에서만 쓸 수 있다(아래 "수식" 절). 수식이 필요 없는 학과는 `features`를 `[]`로 두고 `$` 기호를 쓰지 않는다. 숫자 계산은 `2 × 3`, `1/2`처럼 평문으로 쓴다.
2. **글과 그림으로 배울 수 있어야 한다.** 교시마다 그림이 도움이 되면 넣는다. 그림은 설명을 장식하는 것이 아니라 그림을 보고 풀어야 하는 문항을 하나 이상 만들 정도로 쓴다.
3. **비전공자가 처음 배운다.** 용어는 처음 나올 때 정의한다. 한 교시는 20~35분이다.
4. **정확해야 한다.** 확실히 아는 사실만 쓴다. 모호하면 그 부분을 빼거나 일반론으로 쓴다. 논쟁이 있는 주제는 한 입장을 정답처럼 쓰지 않고 입장들을 균형 있게 소개한다. 책이나 논문의 문장을 그대로 옮기지 않는다. 설명과 예는 직접 쓴다.
5. **자격·조언이 아니다.** 진단, 처방, 법률·투자 조언처럼 읽히는 문장을 쓰지 않는다.
6. **학과 이름이나 다른 학과의 교시를 선행으로 걸지 않는다.** 선행(`requires`)은 같은 학과 안에서만 쓴다.

## 교시 JSON

```jsonc
{
  "trunk": ["xx-01", "xx-02", ...],      // 공통 줄기. 정확히 6교시
  "branches": [],                         // 갈래는 쓰지 않는다
  "lessons": [
    {
      "id": "xx-01",                       // 학과 약어 + 두 자리 번호
      "title": "…",
      "minutes": 25,
      "requires": [],                      // 입구는 [] . 선행은 같은 학과 교시 id
      "features": [],
      "explain": [ "문단", "- 항목\n- 항목", { "figure": "departments/<학과id>/a.svg", "alt": "그림을 보지 않는 사람도 이해할 만한 설명", "caption": "선택" } ],
      "examples": [ { "title": "…", "body": [ "문단", { "figure": "…", "alt": "…" } ] } ],
      "checks": [ … ]
    }
  ]
}
```

- 첫 교시만 입구다. 선행 그래프는 줄기 전체가 첫 교시에서 도달 가능해야 한다. 한 줄로 이어도 되고, 첫 교시 뒤에 두 교시가 동시에 열려도 된다. 순환은 안 된다.
- 마크다운은 `**굵게**`, `*기울임*`, `` `코드` ``, 목록(`- ` 또는 `1. `)만 쓴다. 표와 제목(`#`)은 쓰지 않는다. 문자열 하나는 문단 하나 또는 목록 하나다.
- 문체는 기존 학과처럼 "~다"체로 쓴다.

## 문항

모든 문항은 `type`, `prompt`가 필요하고, `hint`(두 번 틀리면 보임)와 `explanation`(맞히거나 세 번 틀리면 보임)을 넣는다. 그림을 보여 줄 문항은 `"figure": { "figure": "…", "alt": "…" }`을 더한다.

| type | 필드 | 주의 |
|---|---|---|
| `choice` | `options`(2개 이상), `answer`(정답 번호 배열) | 정답이 둘 이상이면 자동으로 복수 선택이다. **정답 번호가 늘 0이 되지 않게** 섞는다 |
| `match` | `pairs`: `[[왼쪽, 오른쪽], …]` (2개 이상) | 오른쪽 문자열은 서로 달라야 한다. 모호한 짝 금지 |
| `order` | `items`: 정답 순서로 적는다 (3개 이상, 중복 금지) | 순서가 하나로 정해지는 것만 낸다 |
| `numeric` | `answer`(숫자), 선택 `tolerance` | 계산이 단순한 것만. 단위는 prompt에 적는다 |
| `keywords` | `groups`(동의어 묶음들), `model`(모범 답안), `selfCheck`(비교 항목들), `minLength` | 묶음 안 단어는 어간 위주로 넉넉히. **자동으로 통과하지 않고** 학습자가 모범 답안과 비교한다. 한 학과에서 많아야 2교시 |
| `submit` | `checklist`, `minLength` | 점수 없음. 직접 해 보는 과제일 때만. 한 학과에서 많아야 1개 |

- 교시마다 문항 3~5개. 서로 다른 유형을 섞는다. `choice`만 나열하지 않는다.
- 교시마다 그림과 연결된 문항을 가능한 한 하나 이상 둔다. 학과 전체에서 최소 3개.
- 오답 선택지는 그럴듯하게 쓰되, 정답이 하나로 확실히 정해져야 한다. 해석에 따라 갈리는 문항은 내지 않는다.
- `expression`은 `formula`를 선언한 교시에서만 쓴다(아래 "수식" 절).

## 수식 (물리·화학·통계·경제·재무·공학 등 계산이 핵심인 학과만)

- 수식이 필요한 교시에 `"features": ["formula"]`를 넣는다. 수식 렌더러는 저장소 안(`vendor/katex`)에 있어 외부 요청이 없다. 선언하지 않은 교시에서는 `$`가 그냥 글자로 보인다.
- 인라인은 `$F = ma$`, 독립 줄은 `$$v = f\\lambda$$`. **JSON 문자열에서 역슬래시는 두 번**(`\\frac`, `\\lambda`) 쓴다. 지원은 KaTeX 범위다.
- `numeric`: 값을 `1/2`, `2pi`처럼 식으로 입력해도 받는다. 단위는 prompt에 적고, 허용 오차가 필요하면 `tolerance`를 쓴다.
- `expression`: 학습자가 식을 쓰면 여러 점에서 값을 넣어 정답 식과 같은지 본다. `answer`는 `3x^2 + 2`처럼 우리 해석기가 읽는 문법(`+ - * / ^`, 괄호, `2x` 곱 생략, `sin cos tan exp ln log sqrt abs pi e`)으로 쓴다. 변수가 `x`가 아니면 `"vars": ["t"]`처럼 적는다. 표본점은 0.3~2.9 구간이다.
- 풀이 과정이 아니라 **결과 값이나 식**을 묻는다. 단위 환산이나 부호처럼 흔한 실수가 정답과 구별되도록 문항을 설계한다.

## 학과 성격별 주의

- **외국어문학(독일어·일본어·중국어·프랑스어·영어)**: 설명은 한국어로 쓴다. 외국어 예시는 **확실히 아는 입문 수준**의 낱말·문장만 쓰고, 번역은 항상 곁에 둔다. 소리는 재생되지 않으므로 발음은 한글 근사 표기와 설명으로 쓰고 "근사"임을 밝힌다. 문자 표(오십음도 등)는 한 글자씩 대조해 틀리지 않게 한다. 실제 문학 작품을 인용하지 않고 직접 쓴 짧은 가상 문장·글을 쓴다.
- **법학·보건행정·사회복지·재무·회계·체육·특수교육·유아교육**: 법률·의료·투자·세무·운동·치료 조언처럼 읽히는 문장을 쓰지 않는다. 가상의 나라·기관·사례를 쓰고 `limits`에 범위 밖을 분명히 적는다.
- **공학 학과**: 설계·안전·시공 판단 지침으로 읽히면 안 된다. 개념과 간단한 계산만 다루고, 고전압·화학약품·중장비 작업 방법은 쓰지 않는다.
- **교육 계열**: 자격·임용·현장 실습과 무관한 이론이다. 실습은 제출형 문항으로만 남긴다.

## SVG 그림

- 파일 하나에 하나의 개념. 가로 300~400, 세로 100~400. `viewBox`와 `width`·`height`를 모두 쓴다.
- 배경 사각형을 직접 칠한다(`#f4efe6`). 글자는 `font-family="sans-serif"`, 크기 11 이상, 글자색 `#1d1c1a`. 강조색은 `#2f5d50`(초록), `#e07a3f`(주황), 보조 `#7a766d`(회색).
- 글자가 도형 밖으로 넘치지 않는지 좌표를 계산해서 확인한다. 한글 한 글자는 폭이 글자 크기와 비슷하다.
- `alt`는 **그림에 보이는 것만** 옮긴다. 그림에 적혀 있지 않은 이름이나 정답(예: 번호만 있는 그림에 "3번은 미토콘드리아")을 대체 텍스트에 더하면, 화면낭독기 사용자에게만 정답이 노출된다. 이름이 필요하면 그림 안에 글자로 적는다.
- 색에만 의존하지 않는다. 라벨이나 모양을 함께 쓴다.
- 외부 참조(`href`, `@import`, 외부 폰트)와 스크립트를 쓰지 않는다. 실제 작품·사진·로고를 흉내 내지 않는다.
- 만든 SVG는 눈으로 확인하기 어려우므로 좌표를 신중히 계산한다.

## 검사

작성하는 동안 반복해서 실행한다.

```bash
node tools/validate-dept.mjs <학과id>
```

스키마, 그림 파일 존재와 `alt`, 선행 그래프, 그리고 **정답 입력은 통과하고 오답 입력은 통과하지 않는지**를 모두 본다. 통과해야 끝이다.

## 마치면

1. 카탈로그에 넣을 값을 지정된 경로(`…/scratchpad/meta/<학과id>.json`, 폴더가 없으면 만든다)에 JSON 파일로 쓴다.

```json
{ "audience": "누구에게 맞는지 한두 문장", "limits": "범위 밖이면 한 문장, 없으면 null" }
```

2. 최종 보고는 **80단어 이내**: 교시 제목 6개, 그림 개수, 검사 결과, 확신 없는 사실(없으면 "없음").
