# Free University 6단계 학사급(Bachelor-Level) 커리큘럼 마스터 플랜

## 1. 목표와 설계 철학

기존 12교시(1단계 공통 줄기 6교시 + 2단계 요약형 갈래 6교시)가 학사 전공의 **목차와 핵심 개념을 훑어보는 지형도**였다면, **6단계 학사 커리큘럼**은 실제 4년제 대학 전공 과정(1학년 기초 → 2학년 전공핵심 → 3학년 전공방법론·심화 → 4학년 캡스톤 종합)의 학습 호흡과 문제 해결 깊이를 정적 웹사이트 안에서 완결성 있게 구현하는 것을 목표로 한다.

- **학과당 총 20교시 (전체 51개 학과 × 20교시 = 1,020교시)**
- **문항 수**: 교시당 4~5문항 표준화 (전체 약 **4,500문항**)
- **시각 도식(SVG)**: 2~5단계 핵심 이론·모형 도식 추가 제작 (학과당 +4개 이상, 전체 **500개 이상 SVG**)
- **비용·독립성 원칙 유지**: 실행 중 외부 API·AI 호출 0건, 화면 코드(`src/`) 내 학과 이름 하드코딩 0건, 어느 학과를 빼도 성립하는 모듈성 100% 유지

## 3. 교시 집필 및 문항 설계 품질 기준 (Quality Bar)

### 3.1 본문(`explain`) 및 예제(`examples`) 기준
1. **유도와 맥락이 있는 6~10문단 구성**:
   - 단순 정의 나열을 금지하고, **(1) 문제 상황과 한계 → (2) 핵심 개념·모형의 도출 원리 → (3) 수식/구조의 단계별 유도 → (4) 시각 도식(SVG) 또는 원전/사례 정밀 독해 → (5) 이론의 한계와 예외 조건** 순으로 서술한다.
2. **단계별 풀이 예제 2개 이상**:
   - 각 교시는 최소 2개의 구체적 예제(`examples`)를 포함하며, 조건 제시 → 1단계 적용 → 2단계 도출 → 결과 해석의 전 과정을 보여 준다.

### 3.2 문항(`checks`) 구성 기준 (교시당 4~5문항)
- **문항 1 (개념·구조 매칭 `match` 또는 단계 배열 `order`)**: 핵심 개념 간 위계, 메커니즘 순서 검증
- **문항 2 (정량 계산 `numeric` / 수식 `expression` / 구조 분석 `choice`)**: 2단계 이상의 사고나 수식 대입이 필요한 응용 문항 (단순 암기 배제)
- **문항 3 (도식 `figure` 판독 또는 복합 사례 `Case Study` 판별)**: 실제 데이터·판례·실험 조건·SVG 도식을 읽고 이론을 적용하는 문항
- **문항 4 (반례·한계·비교 추론 `choice`)**: 두 이론이나 조건이 충돌할 때의 결과를 판별하는 심화 문항
- **문항 5 (각 단계 마감 교시 및 6단계 캡스톤)**: 핵심어 서술(`keywords`) 또는 종합 과제 제출(`submit`)을 배치하여 학습자의 능동적 인출과 자기 점검 유도

## 4. 엔진·스키마·UI 개편 명세

1. **스키마 확장 (`src/engine/schema.js`)**:
   - `branches` 항목에 선택적 `stage` (`2`~`6`) 속성 허용.
   - `b.opensAfter`가 `trunk` 교시뿐 아니라 같은 학과 내 앞선 단계(`branches`)의 교시 ID도 참조할 수 있도록 검증 규칙 확장(순환 참조 금지 및 도달 가능성 검사는 그대로 유지).
2. **진도 엔진 확장 (`src/engine/progress.js`)**:
   - 단계별(`stage 1` ~ `stage 6`) 완료 교시 수와 해금 상태를 계산하는 `stageSummary(dept, dp)` 추가.
   - 6단계 캡스톤까지 모두 마친 상태를 `bachelorCompleted`(`allDone`)로 판정.
3. **학과 화면 개편 (`src/views/department.js`)**:
   - 학과 상단에 **1단계~6단계 학사 이수 로드맵 바(Stage Progress Bar)** 표시.
   - 각 갈래 패널 제목을 `2단계 · 전공필수 I · <갈래명>` ~ `6단계 · 전공종합 V · 학사 캡스톤`으로 명확히 표기하고 선행 해금 조건 안내.
4. **내 진도 화면 개편 (`src/views/progress.js`)**:
   - `1단계 기초 이수` / `2~5단계 전공심화 이수` / `6단계 학사 과정 완주`의 3층위로 성취 현황 시각화.

## 6. 단계별 실행 로드맵 (Implementation Phases)

1. **Phase 1 — 엔진·스키마·UI 6단계 아키텍처 업그레이드**
   - `src/engine/schema.js`: 갈래의 `stage` (2~6) 및 갈래 간 선행(`opensAfter`에 선행 갈래 교시 허용) 검증 지원.
   - `src/engine/progress.js`: 1~6단계별 이수율(`stages`) 및 학사 캡스톤 완주 판정 추가.
   - `src/views/department.js`, `src/views/lesson.js`, `src/views/progress.js`: 1단계~6단계 로드맵 시각화 및 단계별 배지 표시.
   - 단위 테스트(`tests/`) 추가 및 통과 확인.

2. **Phase 2 — 경영·자연 계열 (12개 학과 × 20교시 = 240교시) 6단계 구축**
   - 경영 5개 학과 + 자연 7개 학과의 2~6단계(학과당 14개 심화·캡스톤 교시, 교시당 4문항 + 예제 2개 + 핵심 수식/도식) 전면 구축 및 `npm run check` 검증.

3. **Phase 3 — 공학·교육·예술 계열 (18개 학과 × 20교시 = 360교시) 6단계 구축**
   - 공학 9개 학과 + 교육 4개 학과 + 예술 5개 학과의 2~6단계 전면 구축 및 `npm run check` 검증.

4. **Phase 4 — 인문·사회 계열 (21개 학과 × 20교시 = 420교시) 6단계 구축**
   - 인문 9개 학과 + 사회 12개 학과의 2~6단계 전면 구축 및 `npm run check` 검증.

5. **Phase 5 — 전체 1,020교시 통합 검수·문서 갱신·Git 커밋**
   - `npm test` 및 `npm run check` (51개 학과 × 20교시 = 1,020교시 입구~6단계 캡스톤 자동 풀이, KaTeX 수식, 외부 호출 0건, 학과 이름 독립성) 최종 통과 및 커밋.
